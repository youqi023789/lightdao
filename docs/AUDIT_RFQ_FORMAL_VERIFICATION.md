## 3. 发包前必须闭合的先决条件（我方责任，非供应商责任）

源码↔产物可复现映射尚未全绿：注册表记录的"源码长串命中"比值显示，12 个在用 code 中 **5 个（9 / 12 / 13 / 16 / 17）源码串命中不完整**（例如 11/16、5/12、1/3）。在这些映射闭合前，任何"已审计源码"的声明都可能对不上链上实际字节码。因此：

1. 我方交付：每个 in-scope code 的 `wasmd q wasm code <id>` 原码 + 对应 `contracts/wasm/code<N>_*.wasm` + `wasm/SHA256SUMS` + `wasm/BUILDLOG.tsv`（含构建提交号）。
2. 复现口径：`rustc 1.85` 编译后必须经 `wasm-opt --mvp-features -O3` 归一化，否则 wasmvm v2.2.1 的 wasmer4 会在 DeliverTx 阶段报 `reference-types not enabled`（见 `contracts/AUDIT_REPORT.md` §0）。这是复现构建的已知坑，写进发包材料可省供应商一天工时。
3. 交付前用 `cosmwasm-check`（与 wasmvm 能力集匹配的版本）对每个 wasm 做上传前校验。
4. 验收标准之一：**供应商能独立复现出与链上 code hash 完全一致的产物**。做不到，就先别开始逻辑审计。

## 4. 需要形式化证明的不变量（候选清单，规格由双方共同定稿）

以下按"必须恒成立的性质"给出候选，具体门限取值一律**以部署合约的链上查询结果为准**，本文件不复述。

1. **供给守恒**：铸造+空投+发放总额恒不超 2.5B 硬顶；任意时刻 `总发行 = 各余额之和 + 合约持仓`；未领余额可精确回收且不凭空产生。
2. **每日根的承诺完整性**：`submit_daily_root` 类入口只能由达到授权门限的多签集合触发；同一 `day` 的根唯一（重放/双提交必须失败）；跨天不可重复领取。
3. **Merkle 叶子编码的域分离**：定宽字段（day 用 u64 小端、各计数维度用 u128 小端）+ 字符集受限标识（bech32 地址），使不同 `(标识, 维度)` 元组不可能得到同一 preimage；叶子输入长度 ≠ 内部节点输入长度，排除叶/内部节点二阶碰撞。
4. **归属与释放**：已释放总量对任意时刻单调不减；`Claim` 真实转账且不超过 `f(elapsed)`；时间表不可被非授权方追加或改写（对照 code 9/16/17 的"无 admin"语义）。
5. **赔付门与池不变量**：赔付通过所需门限与权重必须来自链上真实持仓，而非调用者自报；池余额与账本之和不一致必须失败而非静默。
6. **预言机窗口语义**：TWAP 必须是**时间加权**（窗口内按时间积分），且单区块多次报价不能主导窗口；须给出"操纵成本下界"的论证。
7. **子代币集中度上限**：单地址上限的比较基准（铸前/铸后供应量）必须与白皮书 §5.10 语义一致，并证明其在边界值上不误放行。
8. **治理时序**：投票期外不可投票；重复质押不得使投票权超过实际持仓；提案窗口排序（投票期/执行期/时间锁）不可重叠绕过。
9. **多签时间锁**：达到门限仍不能跳过时间锁；不存在"紧急豁免"路径（当前设计为 72h 且不可豁免）。

## 5. 方法学要求（我方审计程序的硬约束）

摘自本仓库既有方法论，供应商必须按同一标准交付，否则不予验收：

- 每条不变量必须做到**执行点 + 检测点 + 告警 + 测试四者齐备且同层**（`docs/AUDIT_PROGRAM.md` 原则）。只有执行点没有独立检测点＝未审计。
- **独立 oracle 重算**：不得用被测系统自报的聚合值验证它自己。每日贡献承诺必须从**原始链事件**（mint/claim/submit_root/burn）重算叶子、树根与加权总分，与网关自报值、链上承诺做三方比对（方法见 `docs/AUDIT_COVERAGE_LEDGER.md` §2）。
- **退化态覆盖**：旧缓存、时钟漂移、无授权、二次升级、断网恢复、升级 halt 等必须进测试矩阵；只测 pristine 状态属于反例库第 2 条。
- **对抗面**：SYBIL 农场、限流绕过、缓存投毒、重放、薅羊毛、稀释与投毒场景需显式覆盖。

## 9. 预算与风险预期（供内部决策，不写进对外询价）

- 公开指南给出的形式化验证常见投入区间为 **$30K–$100K+** 一次承接；多 crate + 规格共创 + 复验，应按该区间上限做心理准备。
- **"证过了"不等于"安全"**：2025 年 5 月 Cork Protocol 在四份独立审计加一次 Certora 形式化验证之后仍损失约 1200 万美元， exploited 的那条性质不在规格里。所以验收必须包含**规格评审会议记录**，而不只是证明结果。
- FV 抓不到运营面风险（密钥托管、预言机数据源质量、治理社工）。因此本 RFQ 必须与安全审计 + 实时经济对账监控（已在运行）打包，而不是替代它们。
- 若预算只够一件事：优先把 §4 的第 2、3、4 条（每日根承诺、叶子域分离、归属释放单调性）做成可机器复核的**独立 oracle 对账**，其性价比高于对全部合约的完整证明。
