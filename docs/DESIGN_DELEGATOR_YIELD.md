# 草案:委托者收益设计变更(Delegator Yield)— DRAFT

## 现状(实测,先纠正一个常见误解)
- 验证者协议收入 = lightfee 手续费分成 30% + v4 的 5% 排放,**直接打入验证者 operator 账户**,不经过 x/distribution。
- 因此**委托人当前实际收益 ≈ 0**;每周 `withdraw-all-rewards` 提的是 distribution 模块余额,目前≈0。
- 白皮书 V2.0 **未承诺任何质押 APY**;质押定位为保证金/资格/治理凭证,并明写奖励来自贡献"而非资本质押"。
- 结论:任何"委托收益"都是**新增设计**,不是兑现既有承诺;文案必须保持"历史收益、非承诺"口径。

## 目标
给委托人真实、可验证、不误导的收益,同时不削弱验证者运维激励、不改动挖矿池。

## 方案对比
- **A 链级路由(consensus,MAJOR 升级)**:把验证者份额改经 x/distribution 发放,佣金机制自动分给委托人。优点:协议级、强制;缺点:共识变更、升级风险高、佣金博弈复杂。
- **B operator 手动分成**:不强制、不透明、不可验证。**否决**。
- **C opt-in 收益共享合约(推荐先行)**:每个验证者可自愿部署/接入一个共享合约,把其协议收入的 X% 按质押占比每日分给委托人;链上可查、可验证、无需共识变更。优点:无升级风险、透明、验证者保留激励;缺点:opt-in 非强制(用披露与排名激励参与)。
- 路线:**先 C 后 A**。C 跑一个赛季,数据与社区反馈支持后再议 A(MAJOR)。

## 参数草稿(C)
- 来源**仅限**:lightfee 30% 分成 + v4 5% 排放;**绝不**触碰每日矿工池。
- 默认共享比例 X=50%(operator 自留 ≥50% 以保运维激励);下限写进合约不可调低。
- 结算周期=每日定稿后(与 settle 同节奏);按当日委托占比 pro-rata。
- 最小委托 1 LIGHT;反女巫沿用现有质押/指纹规则。
- UI 只展示**按实际派发计算的历史年化**(标注"历史收益,非承诺、非 APY 保证");禁止任何"保本/固定收益"措辞(合规)。
- 白皮书增补 §4.x 条文草稿:"验证者可自愿将协议收入的一部分按委托占比分配给委托人;该分配为历史表现,不构成收益承诺。"

## 治理与上线路径
- C 起步无需提案(validator 自愿接入);建议发一个 signal 提案背书默认参数 X=50%。
- 合约:新 rewards_share wasm,测试网 canary 验证后主网;operator 接入=一次 migrate/授权交易。
- A 若推进:x/gov + MAJOR 升级,含参数(佣金区间、分配比例)与回归矩阵。

## 风险与对策
- 佣金竞底/竞高:披露页展示各验证者"共享比例+历史派发",市场自平衡。
- 自委托 sybil:沿用指纹/IP 反女巫;共享合约按地址去重。
- 收益波动被误读为承诺:UI 与文案强制"历史"口径,qa_truth 增加断言(页面不得出现"保证/固定/APY 承诺"字样)。
