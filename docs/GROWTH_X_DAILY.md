# X（推特）日更通道

## 一次 7 天的静默断更（2026-10-09 → 10-16）

`每日X动态` 定时任务从 **10-09 起连续失败 7 次后被停用**，直到 10-16 回头查任务表才发现。
根因不是 X 接口，而是**任务指令里写死了已经退订的老机器**：老 SG 的公网 IP、SSH 用户、以及桌面上一个云厂商 .pem 密钥文件的绝对路径（这三类都属于不允许进公开仓库的基础设施标识，本文件只描述形态、不写值）。阿里/腾讯 8 台老机 10-15 已退订，10-09 之后那台机器上的主机名与路径早已不可用（迁移 10-13 完成，任务指令没跟着改）。

教训：**基础设施搬迁时，所有"引用地址的文本"（脚本、任务指令、文档）必须一起改**，
否则会出现"通道静默死掉、没人知道"。已把这条加进每小时自走执行器的检查项。

## 现状（10-16 实测）

- 取数与出稿：`sudo DRY_RUN=1 /usr/local/bin/ld_daily_x.sh` → 201 加权字符（上限 280），
  数字全部来自链上：区块高度（127.0.0.1:26657）、赛季日与今日矿工（127.0.0.1:8080，
  该端口已收紧为只绑本机，本机调用正常）、销毁量（链上金库销毁地址余额）。
- 合规门禁：`/usr/local/bin/ld_x_compliance.py`，检查加权长度≤280、禁用收益承诺/
  价格预测/稳赚无风险/催购话术（中英）、必须含区块高度与官网链接、不得含 `None`/`nan`/模板占位。
- 反向验证（五项，全部按预期）：真稿 OK；`guaranteed 30% APY, risk free` → FAIL 命中 3 条禁用项 +
  缺锚点；`height None | {} miners` → FAIL 缺锚点 + 未取到变量；空稿 → rc=2；
  构造 363 加权长度 → FAIL 超长。
- 断更期间没有任何"发帖失败但显示成功"的假象：脚本失败即非零退出，任务记 error。

## 恢复计划（已排进定时任务，不靠记忆）

| 阶段 | 任务 | 时间 |
|---|---|---|
| 只出稿 | `LightDAO 每日X日更（只出稿阶段·2026-10-16 重建）` id `f39e6210` | 每天 04:00 UTC，10-17 起 |
| 复核并转真发 | `三天出稿复核与转真发（10-19）` id `46f79c7f` | 2026-10-19 13:00 UTC |

复核任务会逐份过门禁、并把稿里的 height／矿工数／销毁量与链上历史对账，
**任一项不过就维持只出稿**，不允许"差不多就开"。通过后由它把日更任务改成真发，
并手动触发一次确认落地（取回 tweet id），再把切换日期与首帖链接回写本文件。

## 为什么"只出稿三天"

发帖是以项目所有者身份对外的公开行为，按纪律需要逐次授权。用户 10-16 批准的是
"先出稿三天、核对合规后再开真发"这个**流程**，因此切换动作本身不需要再等确认，
但切换的**前提**（三天稿全部过门禁且数据与链上一致）必须由机器检查得出，不能凭印象。
