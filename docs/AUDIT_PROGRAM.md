# LightDAO 审计计划(AUDIT PROGRAM)— 方法论与周期

原则:**审计不是"跑一遍测试",而是对每条系统不变量证明"执行点+检测点+告警+测试"四者齐备且同层。** 任何只有执行点没有检测点的不变量,视为未审计。

## 0. 过去审计为何失效(自我批判,作为反例库)
1. 静态/语法级:只查死链、语法、元素存在,查不出运行时与跨层行为。
2. 快乐路径:只测 pristine 新鲜状态,不测退化态(旧缓存/后台节流/二次升版/无授权/弱网/时钟漂移)。
3. 单层:客户端、网关、链、运维各测各的,不测层间契约(如 cron 时区 vs 日界、显示 vs 链上)。
4. 无时间轴:不在边界跨越/升级窗口/时区切换点跑门。
5. 非对抗:没有攻击者模型,不跑滥用/薅羊毛/稀释/投毒场景。
6. 无独立 oracle:用被测系统自己的输出验证自己(网关验证网关),无第三方重算。
7. 无覆盖账本:不知道"哪些不变量没有测试",缺口不可见。

## 1. 审计类型(缺一不可)
- **安全审计**:密钥托管/共识/合约经济/治理完整性/网关数据完整性/客户端(XSS·CSP·供应链)/可用性(DoS·升级 halt)/隐私(指纹·IP)/运维管线/头部与限流可信性(X-Forwarded-For 类)。
- **经济对账审计(独立 oracle)**:每日从**原始链事件**(mint/claim/submit_root/burn)重算:总供应守恒、每日池==矿工 payout+验证者份额+未领、total_score==叶子加权和、空投账本==事件;任何不等即告警。不信任网关/合约的自我报告。
- **运维/DR 审计**:备份可恢复性(真恢复一次)、cron 时区与意图一致、升级/迁移原子性与回滚演练、证书/DNS/域名到期、磁盘/日志轮转、监控自身存活(哨兵故意注入故障看是否报警)。
- **合规/隐私审计**:文案无收益承诺(APY/保本)、指纹与 IP 的留存期限与披露、用户数据导出/删除路径。
- **供应链/构建审计**:cargo/cosmjs/wasm-opt 版本与来源固定、SRI、构建可复现(hash 比对)、staging 灰度门。
- **UX/真相审计**:显示==真相(徽章/状态/可领/倒计时)在退化态下仍成立;错误必有可见反馈。
- **治理流程审计**:编号系统不混(x/gov vs 合约)、窗口排序、投票/执行权限、提案文本与白皮书一致。
- **容量/性能审计**:心跳 QPS、网关单点吞吐、区块气体上限、日志增长。

## 2. 周期(机器自执行,见 QwenWork 定时任务,不依赖任何人的记忆)
- 每日 06:30 UTC:经济对账(独立 oracle)+ 结算 SLA 检查。
- 每周一 02:00 UTC:红队演练(testnet:sybil 农场、XFF/限流绕过、缓存投毒、时钟漂移、重放、断网、升级 halt 恢复)。
- 每月 1 日 03:00 UTC:全量审计(上述 8 类逐条过,产出覆盖账本 diff)。
- 每次发布:灰度四门(qa_site/qa_extra/site_audit/qa_truth)+ qa_lock + qa_click + staging。
- 每次链升级/迁移:验收 cron + 回滚演练。

## 3. 不变量登记表格式(六元组)
`不变量 | 层 | 执行点 | 检测点 | 告警 | 测试 | 状态(已证/缺口/接受风险+理由)`
登记表维护在服务器私有 OPS_ROADMAP(含敏感项),公开仓库只保留方法论与已脱敏条目。
