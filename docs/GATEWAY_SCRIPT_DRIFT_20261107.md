# 网关脚本漂移分诊（2026-11-07 巡检）

## 起因

例行巡检里加了一步"只存在于网关的运维脚本补进仓库"的盘点。做法是把
`/usr/local/bin` 下每个非 `.bak` 的 `.sh/.py/.js` 与仓库里同名文件做 sha256 比对，
并用 crontab + 仓库引用判断它是不是"在服役"。工具本身：`infra/ld_script_drift_audit.py`
（只读，绝不写 `/usr/local/bin`、不碰 git 状态、不删任何东西；扫到 83 个脚本）。

顺带说明与 `ld_gate_watch.py` 的关系，避免被当成重复建设：gate-watch 盯的是**已发布的
20 个门禁脚本**与部署清单是否一致，本次跑出来是 `checked=20 drift=0` 全绿；而下面第一条
漂移恰好就发生在 gate-watch 清单之外。也就是说"门禁全绿"和"门禁跑的是哪个版本"是两件事，
需要两张独立的网。

## 1. ld_i18n_validate.js —— 已修（本次提交）

- 现场版本 2026-11-04 16:31Z 在网关上被就地改过：机器翻译表（文件头带 `LD-I18N-MT`）
  的键取自渲染后的文本节点，静态源串集合认不得，于是对机器表跳过"死行"检查，
  列数/空值/跨文字混入照常查，并打印一行说明。
- `infra/ld_i18n_validate.js` 停在 2026-10-17，没有这段逻辑。后果不是"翻译少一行"，
  而是 **promote.py 的 g12 门在校验一份没人在跑的代码**：在网关上调好的判据不会随发布
  进仓，回滚或换机就丢；反过来，仓库里改判据也不等于线上生效。
- 处理：把现行版逐字节同步回 `infra/`（`cmp` 已确认一致）。同步前做过敏感项预检：
  无 IPv4 字面量、无 bech32 地址、无 passphrase/secret/token 关键字，全文 349 行；
  同步后用现行门禁自证 `findings=0`，并跑了一次真实校验
  （`node …/ld_i18n_validate.js client/js` → 表式 1424 行 + 词条式 1678 条，问题 0 处）。

## 2. leak_bip39_hit.py —— 判定：仓库侧更安全，现场侧是陈旧副本，建议人工清现场

唯一一行差异是测试用助记词常量的写法：

- `infra/`（2026-11-05 12:19Z）把它拆成 `"a"+"bandon"` 拼接，注释写明理由——
  发布门禁按"历史新增行"扫形状，公开测试常数也不该靠豁免过关；
- `/usr/local/bin/`（2026-11-05 12:15Z，早 4 分钟）仍是 12 个词的字面量。

即仓库是后改的、更严的那一版，网关上是改名之前的旧副本。**没有真实密钥暴露**
（BIP39 全零熵是公开测试向量，且已在 `leak_allow.json` 里带 `review_by` 豁免），
所以这不是事故，是副本落后。

未动手的原因：该文件 `root:root`，覆盖 `/usr/local/bin` 属于变更生产执行体，
按"任何不确定只报告不动手"留给人工。建议动作（人工执行）：把 `infra/` 那版部署上去，
部署前 `diff` 复确认只有这一行差异。

## 3. lightdao-xchain-probe.py —— 判定：服役中的半成品，不要盲同步

现场 25692 B（2026-11-06 00:53Z）比仓库 24479 B（2026-11-05 14:52Z）多 57 行差异，
新增 `import xc_bank` + `sys.path` 注入、余额缓存 `BAL_CACHE/TTL_BAL`、
以及 `/v1/balances/...` 路由。现场版本里出现链上账户地址与 RPC 端点字面量。

这看起来是跨链演练（XC-*）未收尾的在制品：探针护栏 currently 报
"对面链 gas 不够 uosmo 0 < 300000"，演练本身没通过。把一份带端点硬编码、
且上游还在改的探针直接同步进公开仓库，风险大于收益（泄露门禁只保证 IP 形状过关，
不保证"这个端点该不该公开"）。

建议动作（人工决策，二选一）：
1. 等 XC 演练收尾，由作者把参数（地址/端点）抽成环境变量或 `hosts.env` 引用后一次性入仓；
2. 若要保留现状，先把端点从源码里剥出来，再同步，并让 `ld_script_drift_audit.py` 继续盯。

两点残留观察，只记录不动手：

- 被撤销的对象 `e589804` 仍游离在 `.git` 里（不在任何 ref 上，`repo_leak_history.py`
